# v0.1.22 부분 검수와 반복 검수 생략 기록

사용자가 “Test seems too long. can't we skip some tests?”라고 요청한 뒤,
실제 검수 1회 통과, 현재 부분 검수, Codex 하위 작업 완료 후 Unknown 표시를
알리고 생략 범위를 제시했다. 사용자는 “예외 출시: 반복 검수 생략 (권장)”을
선택했다. 승인 범위와 운영 절차는 [설계 1.0](../design/2026-10-08-macos-next-release/v0.1.22-validation-exception.md)에 고정한다.

이 기록은 태그 v0.1.22, commit `80a0576246ecc25b91d4889e015c07e4ffc30bca`,
tree `b53b60e283cca361e0898fcb5f2ba35fad93c602`, 격리 설정 hash
`229c2bb2a8b029506dd969cc9ebfbfae35ad1b81b4d3a70afba89c89269cd938`에만 적용한다.
[기계 승인 기록](v0.1.22-native-validation-exception.json)은 동일 후보,
사용자 선택, 등록 시점, 부분 검수 원본과 독립 평가의 hash를 보존한다.

## 통과·관찰·생략의 구분

- release PR의 CI 7개와 같은 tree에서 실제 검수 3회차의 독립 판정은 통과했다.
- 4회차에서 native 업데이트 fixture, shell PID·창·탭 유지, picker, Sessions,
  주요 sidebar·quota·review·preparation 동작을 관찰했지만 전체 통과 회차로 세지 않는다.
- Codex 하위 작업의 실제 완료 record와 부모 done 표시 뒤에도 같은 child는 Unknown이었다.
  CHILD-161 완료 상태 전이가 실패했으며 실제 모델 작업의 실패를 뜻하지 않는다.
- 정상 종료 후 두 provider가 동일 session/conversation resume 인자로 다시 실행됨을 확인했다.
  대화 본문 전체 복원을 입증했다고 확대하지 않는다.
- fresh multi-block source-match Copy, 남은 sidebar·닫기 변형, 실패·복구 재시도,
5회차와 두 전체 네이티브 E2E는 생략했다. 기존 fixture preview 증거와 구분한다.

4회차 원본의 blocked 판정을 보존한다. schema 2는 `native_result: blocked`,
`observed_failures: [CHILD-161]`을 유지한다.
정규 3회차 검수나 전체 인수조건의 통과 자료를 만들지 않는다. 발견된 상태 표시
문제와 기존 후속 문제를 해결 또는 완료로 닫지 않는다.

## 생략하지 않는 공개 조건

등록된 Developer ID와 업데이트 key로 만드는 universal signed ZIP의 서명·공증,
stapled ticket·Gatekeeper·Ed25519·버전·수동 업데이트 설정을 검사한다.
draft ZIP의 실제 실행·세션 유지 업데이트·GUI IPC·원래 shell PID 보존은
정확한 ZIP hash와 독립 검토한 원본 hash를 갖춘 통과 자료가 있어야 공개할 수 있다.
이 네 검사는 이번 예외의 생략 목록에 들어갈 수 없다.

main의 검증기와 승인 기록을 태그 checkout 전에 동결한다. 공개 단계는 빌드 뒤
정확한 ZIP, 같은 승인 기록과 별도 최신 재확인을 요구한다. 같은 draft만 공개하고
latest·Homebrew 및 공개 후 독립 다운로드·서명·Pages를 확인한다.
