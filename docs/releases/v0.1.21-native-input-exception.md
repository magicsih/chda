# v0.1.21 공개 지시와 미완료 검수 기록

2026-10-09 사용자는 macOS 자동 클릭 실패, 실제 전체 검수 통과 0회,
v0.1.21 미공개 상태를 전달받은 뒤 “이제 좀 공개해라 좀”이라고 지시했다.
이 지시를 이번 버전의 미완료 네이티브 검수를 감수한 공개 요청으로 해석했고,
그 해석과 서명·공증·업데이트 서명·공개 다운로드 검증의 유지 여부를 대화에 알렸다.
새로운 검수 통과나 원래 설계 1.2의 인수조건 충족을 주장하지 않는다.

원래 14개 개선과 #173 보류, Windows/Linux 기능 티켓 제외는 유지한다.
release-plz PR #167의 squash commit
`4e4116560d4e2915830bdbb447566b5d5fabad9e`, tree
`f198127022e0a3aabd9162da3c663998d7ce627a`에만 적용한다.
제품 코드, 버전, CHANGELOG와 산출물을 바꿔 예외를 적용하지 않는다.
승인 1.2 원문과 이전 실패·차단 근거는 보존한다.

## 미완료 항목

- 실제 macOS 개발 실행 환경 전체 기능 독립 검수 3회
- 빌드 직전 및 공개 직전의 별도 전체 네이티브 E2E
- 정확한 공개 ZIP의 실제 GUI 실행·세션 보존 업데이트·GUI IPC·원래 shell PID 보존 검수

수동 탭 클릭은 실제로 전환됐지만 자동 클릭은 `noWindowsAvailable` 또는
효과 미확인으로 막혔다. 독립 검수자는 원본 전후 캡처를 확인했다.
이 결과는 앱 전체 기능 정상이나 자동 입력 성공의 근거가 아니다.
이전 disposable 업데이트 fixture 통과를 이번 ZIP 검수로 재사용하지 않는다.

## 유지하는 검사와 공개 절차

[기계 기록](v0.1.21-native-input-exception.json)은 정확한 태그·SHA·tree·설정 hash,
사용자 지시, 해석, 시점, 실패 자료와 독립 판정의 hash, 미완료 항목을 고정한다.
Release는 main의 검증기와 이 기록을 태그 checkout 전에 동결한다.
schema 2 자료는 `native_result: blocked`를 유지하며 검수 회차를 만들지 않는다.
다른 버전, 후보, 설정, 기록 hash 또는 누락된 미완료 항목은 허용하지 않는다.

기존 GitHub-hosted 빌드와 등록된 자격증명으로 universal 앱을 만들고
Developer ID, 서명, 공증, stapled ticket, Gatekeeper, arm64/x86_64,
앱 버전과 수동 업데이트 설정, 실제 ZIP의 Ed25519 서명을 검사한다.
draft의 hash·size·appcast·checksum을 재검사하고 같은 파일만 공개한다.
기록은 60분 이내 재확인하며 공개 단계는 빌드 뒤 정확한 ZIP hash를 요구한다.
Latest 역행 방지와 Homebrew hash 대조도 유지한다.

공개 노트와 공개 자료에 미완료 네이티브 검수를 표시한다. 공개 후에는 독립
다운로드로 서명·공증·업데이트 서명·hash·Latest·Homebrew·Pages를 확인한다.
미완료 기능 검수와 티켓 인수조건을 완료로 닫지 않는다.
일반적인 skip 옵션이나 전역 권한 확대는 추가하지 않는다.
이 기록과 검증 경로는 v0.1.21의 추후 공개 자료 및 Homebrew 복구 검증에도 사용한다.
