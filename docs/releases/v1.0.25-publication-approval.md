## 보존한 실행 결과

- 최종 release PR의 CI 7개가 통과했다. macOS UI scenario 226개와 Linux·Windows
  빌드를 포함한다. squash 병합 후 tree가 검수 후보와 같은 것을 확인했다.
- 현재 후보의 정식 네이티브 1회차는 43조건 중 일부 확인 21개·미실행 21개·차단
  1개, 13영역 중 일부 확인 10개·미실행 3개다. 전체 통과 조건·영역과 완료 회차는
  모두 0개다. 두 추가 회차 및 별도 최종 SHA의 두 전체 E2E는 실행하지 않았다.
- 입력을 받는 창과 캡처 창의 불일치가 재연결과 독립 관찰 뒤에도 남아 추가 입력을
  중지했다. 도구의 창 선택과 앱의 창 활성화 중 원인은 미확정이다. 앱·원래 셸이
  살아 있고 새 chda 충돌 진단은 없었다.
- 실제 Codex의 새 QA 응답과 자식 완료 상태를 관찰했다. 전체 Claude·MCP
  list/read/wait·재개 검수의 통과로 확대하지 않는다. 상속된 MCP가 시작된 시도는
  모델 요청 전에 종료하고, 다음 시도에서 기존 MCP·플러그인을 실행별로 끄고
  격리된 QA 서버만 연결했다. 전역 CLI 설정과 폴더 신뢰는 변경하지 않았다.
- 별도의 Developer ID 임시 업데이트 자동 시험 7개는 통과했다. 실제 PTY·GUI·IPC로
  설치·오류·취소·인계를 확인했지만 합성 인계 모델을 쓰므로 실제 CUA 회차나
  정확한 배포 ZIP 검수의 근거가 아니다.
- Slack 작성창 로그인, 관리자 소유 설치·인증 취소 화면과 공개 전 정확한 draft
  업데이트 경로는 차단 상태다. production 환경설정이나 서명 원본 앱의 피드를
  바꾸지 않았다. 기준 QA 설정은 원래 바이트로 복원했다.

## 이번 공개 범위

사용자 지시에 따라 미완료 네이티브 검수, 세 회차의 전체 통과, 두 전체 E2E와
정확한 서명 ZIP의 GUI 실행·세션 보존 업데이트·GUI IPC·셸 PID 검수를 이번 공개의
필수 통과 조건에서 제외한다. 공개 증거는 `schema: 2`, `native_result: blocked`와
미완료 7항목을 유지한다. 미실행·차단을 통과로 바꾸지 않는다.

release-plz의 정확한 태그와 기존 활성 Developer ID·Apple 공증·Sparkle 키를 사용한다.
universal 아키텍처, Developer ID 서명, 공증·stapled ticket·Gatekeeper, ZIP 해시,
appcast·Ed25519 업데이트 서명, 동일 draft assets 공개, Homebrew·Pages 읽기 확인은
기존 절차대로 실행한다. 공개 ZIP을 재빌드하거나 교체하지 않는다. 공개 후 파일·서명·
피드·사이트 확인도 실제 GUI 검수 완료와 구분한다.

검증기는 main의 정확한 승인 bytes와 후보 SHA·tree·설정, 단계별 새 readback,
60분 freshness와 정확한 immutable ZIP을 요구한다. 이후 버전은 이 승인을 사용할 수
없으며 정상 43조건·13영역 계약을 유지한다.
