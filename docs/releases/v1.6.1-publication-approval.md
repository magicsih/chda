# v1.6.1 한정 공개 승인과 미완료 검수

사용자는 미검수 범위와 실제 업데이트 뒤 터미널 보존 미확인을 전달받고
“이번 v1.6.1에 한해 생략 승인”을 선택했다. [승인 기록](v1.6.1-publication-approval.json)은
다음 후보만 허용한다. 과거 승인이나 이 승인을 다른 후보에 재사용할 수 없다.

- 태그: `v1.6.1`
- 최종 커밋: `443d00f0963604a693ada49bcbc8b66769fc20d4`
- 전체 tree: `e063e841fcf22f16f617bb1e37948512cb610bb2`
- 격리 설정 SHA-256: `2043325bab8fa1876532ed4d8e146d0ec082de5bf1752b39da17146571819731`

승인 때 검토한 PR #308의 `e77c095`와 최종 태그의 전체 tree가 같다.
release-plz가 버전과 태그를 생성했다. 태그 생성은 공개 출시를 뜻하지 않는다.

## 생략을 승인한 항목

- 전체 독립 native 검수 3회.
- 전체 before-build native E2E 1회와 before-deploy native E2E 1회.
- 정확한 signed ZIP의 GUI 실행, 앱 자체 업데이트 뒤 세션 보존, GUI IPC와 원래 shell PID 보존 검사.

정상 native 결과는 `blocked`로 유지한다. 실제 업데이트 뒤 기존 터미널 보존은
이번 ZIP으로 확인하지 않았다. 파일과 서명 검증을 위 GUI 검사 통과로 기록하지 않는다.

## 실제 확인한 범위

릴리스 PR의 CI 26개가 통과했다. macOS와 Linux workspace 테스트, 경고를 오류로
처리하는 Clippy, Windows 빌드와 Linux 패키지 검사가 포함된다. 앞선 구현 수정에서
로컬 테스트 540개가 통과했고 기존 제외 항목은 5개였다.

이전 후보에서 발견한 밝은 테마의 diff 대비 결함은 수정했고 개발 앱에서 밝고 어두운
테마와 선택 상태의 가독성을 독립 확인했다. 이 부분 검수를 최종 후보의 전체 통과로
재사용하지 않는다. 최종 후보 검수에서는 실제 shell 입력과 출력을 일부 관찰했지만,
43조건과 13영역의 완전한 통과는 0회다. 입력 대상과 화면 수집 문제가 기록됐고
제품 원인은 확인되지 않았다. 해당 검수의 provider 요청은 0회였다.

이전 v1.6.0 후보의 Codex 출력과 TextEdit, 웹 입력창 사이의 부분 복사 관찰은
최종 후보 검수 통과에 포함하지 않는다. Slack은 미사용이며, 승인된 TextEdit과
웹 입력 대체 검수도 최종 후보의 전체 matrix를 완료하지 못했다.

## 유지하는 공개 조건

CI, 기존 Developer ID 서명, Apple 공증, Gatekeeper, arm64와 x86_64,
Sparkle Ed25519 업데이트 서명, ZIP checksum, 정확한 태그와 SHA와 tree와 설정,
변경하지 않은 draft 파일의 공개, 공개 다운로드와 latest 및 Homebrew 확인은 유지한다.
서명된 공개 ZIP을 다시 빌드하거나 교체하지 않는다.

검증기는 main에 커밋한 승인 JSON의 정확한 바이트를 고정하고 단계마다 새로운
schema 2 readback을 요구한다. 공개 직전 readback은 빌드 뒤 작성하고 동일 archive의
SHA-256을 포함한다. 모든 미완료 항목과 `native_result: blocked`를 공개 증거와
출시 안내에 유지한다. 다른 버전의 정상 native 검수 조건은 바뀌지 않는다.

원본 증적은 `smb://nas1dual/Data/Backup/agent-artifacts/chda/2026-10-26/`의
후보별 보관 목록과 최종 `2026-10-27/443d00f0963604a693ada49bcbc8b66769fc20d4/`
보관 목록으로 연결한다. 자격증명과 provider 개인 설정 사본은 공개 증거와
일반 증적 이관에 포함하지 않는다.
