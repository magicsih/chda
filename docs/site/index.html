chda

A terminal with a git worktree sidebar and a live status board for coding agents.

brew tap magicsih/tap && brew trust magicsih/tap && brew install --cask chda

Why a worktree terminal

One worktree per task

Create a worktree from the sidebar, from any branch, with a note saying what the task is. Work in it, read its diff, merge it back and clean it up.

Agents you can see

Claude Code, Codex, Gemini CLI, Copilot CLI and OpenCode report through chda's hooks. A dot tells you who is working, who is waiting for you, and who is done.

Ghostty inside

The VT core is libghostty-vt, so escapes, Unicode and keys behave like Ghostty. Your Ghostty font, colors and ligatures carry over.

Agents can drive it

chda mcp lets an agent create a worktree, open a tab or report its status. New worktrees show up in the sidebar at once.

Pick up where you left off

After a restart, tabs, splits and directories come back, and panes that ran an agent reopen its conversation. Past sessions resume side by side.

More than text

Images through the Kitty graphics protocol, Mermaid diagrams rendered offline, and right-click actions on every file path in the output.

Install

brew tap magicsih/tap
brew trust magicsih/tap
brew install --cask chda

macOS 14 or newer on Apple silicon. Signed and notarized. Needs git; gh, glab or tea add pull request badges for GitHub, GitLab or Gitea. Prefer a zip? Get it from the releases page.

Questions

Does chda read my prompts?
No. Hooks pass only a session id, directory, event kind and time. Nothing is sent anywhere; the app makes no network requests of its own.
Do I have to change my agents' config?
No. chda passes hook settings per launch and leaves your config files alone. Only the optional MCP server is added once per agent, with the agent's own mcp add command.
Linux or Windows?
They build in CI and are the next milestone. Today it is macOS only.
