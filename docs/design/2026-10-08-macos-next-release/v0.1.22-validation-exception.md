# v0.1.22 검수 범위 예외 — 설계 1.0

2026-10-11 사용자는 반복 UI 회차와 두 전체 네이티브 E2E를 생략하고,
미확인 항목과 Codex 하위 작업의 완료 후 Unknown 표시를 기록하는 선택지
“예외 출시: 반복 검수 생략 (권장)”을 승인했다. 실제 서명된 ZIP의 실행,
세션 유지 업데이트, GUI IPC, 원래 shell PID 보존과 서명·공증·업데이트 서명은 유지한다.

## 범위와 근거

release-plz PR [#202](https://github.com/magicsih/chda/pull/202)의 검수 HEAD
`218d6c1ca523a47932f062aa521169a19bb4bf36`과 squash 후보
`80a0576246ecc25b91d4889e015c07e4ffc30bca`는 실제 Git tree
`b53b60e283cca361e0898fcb5f2ba35fad93c602`가 같다. CI 7개는 통과했다.
기존 후보의 실제 검수 3회차는 독립 검수에서 통과했고, 4회차는 부분 검수다.
5회차와 빌드·공개 직전 전체 E2E는 실행하지 않는다. 미실행을 통과로 만들지 않는다.

Codex가 하위 작업을 완료하고 부모가 done을 표시했지만 chda의 같은 하위 작업은
Unknown으로 남았다. 실행 자체의 실패가 아니라 CHILD-161 완료 상태 전이 실패다.
사용자에게 이 관찰을 밝힌 뒤 위 선택을 받았다. 제품 수정이나 해결을 주장하지 않는다.

범용 skip 인자나 미래 버전의 자동 예외를 만들지 않는다. 정규 schema 1의
3회차·전체 coverage·두 별도 E2E 요구는 유지한다. main 검증기의 commit과
릴리스 태그 commit은 실행 기록에서 각각 확인한다.

## 검증과 실패 처리

변경 전에 새 한정 예외의 정상 입력이 기존 검증기에서 실패함을 확인한다.
후보·선택 문구·실패 목록 변조, signed 검수 누락·실패·다른 ZIP은 거부하는
회귀 테스트로 확인한다. 기존 릴리스 정책 테스트와 문서 생성 검사를 실행하고
최종 PR HEAD에 읽기 전용 Claude 교차 리뷰를 요청한다.

제품 UI 변경이 없으므로 이 정책 PR의 가상 UI 검수는 만들지 않는다.
실제 signed 검수는 별도이며, 실패하면 공개하지 않고 동일 draft를 보존한다.
빌드 및 공개의 60분 이내 승인 재확인, 서명·공증·Ed25519, immutable assets,
latest 역행 방지, 기존 Homebrew 동기화와 공개 후 독립 다운로드는 유지한다.
공개한 ZIP을 다시 빌드하거나 바꾸지 않는다.
