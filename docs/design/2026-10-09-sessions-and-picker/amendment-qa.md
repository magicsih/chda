## CHILD-161 재정의 (2026-10-11 승인)

chda가 Codex에 붙이는 `-c` 설정 때문에 Codex 세션은 공유 서버 밖(embedded)에서 돈다. 그래서
`thread/list`는 실행 중인 하위 에이전트를 상태 DB의 NotLoaded로만 본다(#173과 같은 원인). chda는
스레드를 재개하거나 모델을 호출해서 이 정보를 얻지 않는다.

- **Codex 하위 에이전트**: 실행 중에는 Unknown, 끝나면 Turn complete 또는 Ended. 더 적은 정보가 이미
  확인된 상태를 덮어쓰지 않고(#221), 그룹 머리글이 `0 active`라고 주장하지 않으면 통과다.
- **Claude 하위 에이전트**: 기존 기준(Working·Waiting·Turn complete·Ended 구분)을 그대로 적용한다.
- 근거: [ADR 0015](../../decisions/0015-provider-confirmed-child-activity.md), #173 재검증 기록.

## 터미널 크기 변경 크래시 (2026-10-11 승인)

크기를 바꿔 행이 늘 때 화면이 위로 스크롤돼 있으면, ghostty `PageList.grow()` 안의 무결성 검사
(`ViewportPinInsufficientRows`)가 실패한다. 검사가 켜진 debug 빌드만 종료되며, 배포용 ReleaseFast는
이 검사를 빌드하지 않는다. 무작위 시퀀스 300개에서 ReleaseSafe(assert 유지)의 종료는 0건이었고, 상위
패치를 넣은 빌드와 상태가 같았다. 최신 ghostty `main`에도 남아 있는 상위 버그다.

- 제품 코드에 우회 처리를 넣지 않는다.
- 실제 검수 빌드는 Rust를 debug로 두고 터미널 라이브러리만 `LIBGHOSTTY_VT_SYS_OPTIMIZE=ReleaseSafe`로 빌드한다.
  ReleaseSafe의 assert 실패는 그대로 실패로 기록한다.
- 상위 보고는 ghostty 정책(Issue Triage Discussion, AI 사용 공개, 사람의 검토·편집)에 따라 사용자가 올린다.
- 상위 수정 반영과 reflow 버그(R2-F4) 수정을 위한 라이브러리 갱신은 #224에서 한다(이번 릴리스 제외).
