CHDA · DESIGN 1.3 · 2026-10-09 · 합성 시안

세션을 눌러도 사이드바는 제자리에

ACTIVE와 IDLE을 Sessions 하나로 합치고, 세션 목록과 프로젝트 목록을 따로 스크롤합니다. 세션을 누르면 PROJECT가 그 브랜치를 강조하지만, 움직이는 것은 PROJECT 영역뿐입니다. Add repo는 macOS가 선택 창을 만들지 못해도 앱을 멈추지 않습니다.

이 페이지의 화면은 합성 데이터로 그린 설계 시안입니다. 실제 앱 화면이나 검수 결과가 아닙니다. 본문 정본은 design.md입니다. 관련 이슈: #182, #181.

03 · 무엇이 PROJECT를 움직이나

PROJECT 강조는 지금 포커스한 세션의 브랜치를 따라갑니다. 움직일 때는 #149 규칙(보이는 행은 그대로, 잘린 행만 최소 이동, 저장소 이름 고정)을 PROJECT 영역 안에서만 적용합니다. Sessions는 어떤 경우에도 스스로 스크롤하지 않습니다.

04 · 좁고 낮은 창에서도 두 영역 모두

글자를 줄이지 않고 행을 말줄임으로 자르며, 전체 이름은 tooltip으로 보여 줍니다. 낮은 창에서도 세션 약 5행과 PROJECT가 함께 보입니다.

#181 · PICKER-181

05 · Add repo가 실패해도 계속 쓸 수 있다

macOS가 폴더 선택 창을 만들지 못하면 앱이 멈추는 대신 알림 기록에 오류 한 건을 남깁니다. 터미널 포커스와 입력 중인 글자, 설정, 세션은 그대로이고, 바로 다시 시도할 수 있습니다.

+ repo · 메뉴 · cmd-shift-o · 팔레트→ 선택 창 생성 시도→ 성공: 폴더 여러 개 선택 → 등록 취소: 아무 메시지 없음 실패: 오류 알림 1건 · 앱 계속 실행→ 다시 시도 또는 폴더를 사이드바에 끌어다 놓기

구현: GPUI의 prompt_for_paths는 분리 실행한 작업 안에서 panic하므로 Add repo는 chda가 직접 만든 선택 창을 씁니다. msg_send!로 NULL을 받을 수 있게 생성하고, NULL이면 Unavailable을 돌려줍니다. Linux와 Windows는 기존 GPUI 경로를 그대로 씁니다.

검토에서 고정할 범위

  • #181: chda가 직접 만드는 폴더 선택 창, 실패 알림 문구, 재시도. Linux/Windows는 GPUI 경로 유지. 실제 실패는 실행 파일 교체로 먼저 재현하고, 안 되면 debug 빌드 전용 주입을 씁니다.
  • #182: Sessions 한 섹션, 에이전트 pane마다 한 행, 상태 변화에도 고정된 순서, 터미널 행 맨 아래, 두 영역 독립 스크롤과 40% 상한, 스스로 움직이지 않는 Sessions, 포커스한 세션의 브랜치를 PROJECT 안에서만 강조·최소 이동, 접기 설정 이전.
